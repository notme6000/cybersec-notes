System logs act as the "black box" flight recorders of an operating system. They track system performance, software applications, security actions, and hardware adjustments. Understanding logs is a fundamental requirement for troubleshooting system issues, diagnosing performance drops, and investigating security incidents.

---

## 🪟 Part 1: Windows Logs (Windows Event Logs)

Windows handles logging differently than Linux. Instead of using plain-text files, Windows stores logs in a structured, binary file format with an `.evtx` extension.

### 1. What are they used for?

* 
**Troubleshooting Crashes:** Pinpointing why an application failed or why the OS displayed a Blue Screen of Death (BSOD).


* 
**Security Auditing:** Monitoring who is trying to log in, recognizing unauthorized privilege escalation, and detecting malware creation processes.


* 
**System Health:** Tracking hardware health, low storage warnings, and Windows Update installations.



### 2. Where are they located?

* 
**Raw Binary Files:** The system stores `.evtx` files natively in the following folder:
`C:\Windows\System32\winevt\Logs\` 


* **Key Core Logs:**
* 
**`System.evtx`:** Tracks OS components, driver initializations, hardware changes, and global errors.


* 
**`Security.evtx`:** Focuses on auditing policies (successful/failed logins, privilege tracking, object access).


* 
**`Application.evtx`:** Holds messages, warnings, and errors generated by installed third-party programs or software.


* 
**`Setup.evtx`:** Contains logs generated during Windows installation and system updates.





### 3. How do you read them?

#### Method A: The Graphical Interface (Event Viewer)

This is the most common approach for Windows administrators.

1. Press **Win + R**, type `eventvwr.msc`, and press **Enter**.


2. In the left panel, expand **Windows Logs** and choose a category (e.g., *Security*).


3. The center pane shows the chronological list of events. Click any log to open the *General* and *Details* tabs below it to read its contents.



#### Method B: Using PowerShell (For Automation)

If you prefer the command line or need to scan logs quickly, use the `Get-WinEvent` cmdlet.

* **View the latest 5 errors in the System log:**
```powershell
Get-WinEvent -LogName 'System' -MaxEvents 5 | Where-Object {$_.LevelDisplayName -eq "Error"}

```


* **Filter for a specific security Event ID (e.g., ID 4624 = Successful Login):**
```powershell
Get-WinEvent -LogName 'Security' -FilterXPath "*[System[EventID=4624]]" -MaxEvents 10

```

## 🐧 Part 2: Linux Logs

Linux primarily handles logging via plain text data, which makes parsing logs flexible and lightweight. Modern Linux systems rely on two complementary engines: the traditional text-based `rsyslog` and the binary `systemd-journald`.

### 1. What are they used for?

* 
**Service Management:** Reviewing why web servers (Apache/Nginx), databases (MySQL), or SSH services fail to boot.


* 
**Authentication Audits:** Tracking every `sudo` execution, SSH attempt, and system access attempt.


* 
**Kernel & Hardware Reporting:** Capturing low-level hardware issues or memory shortages.



### 2. Where are they located?

Almost all plain-text log streams live in a central directory: `/var/log/` 

* **Core Operating System Logs:**
* 
**`/var/log/syslog`** (Ubuntu/Debian) or **`/var/log/messages`** (RHEL/CentOS): The master dashboard file for general system-wide events.


* 
**`/var/log/auth.log`** (Ubuntu/Debian) or **`/var/log/secure`** (RHEL/CentOS): Tracks authentication logs (successful/failed logins, SSH activity, account creations).


* 
**`/var/log/kern.log`:** Dedicated strictly to the Linux kernel and hardware messages.


* 
**`/var/log/cron`:** Records scheduled background tasks (cron jobs).




* **Binary Audit Logs** *(Cannot be viewed with a normal text editor)*:
* 
**`/var/log/wtmp`:** Records successful logins/logouts history.


* 
**`/var/log/btmp`:** Records failed login attempts.





### 3. How do you read them?

Because most Linux logs are plain text, you use command-line file utilities to isolate information.

#### Tool 1: `less` (For manual browsing)

Opens the file interactively without loading the entire document into memory.

```bash
sudo less /var/log/syslog

```

* 
**Navigating `less`:** Press **G** to skip to the end of the file, **/** followed by a keyword to search forward, and **q** to quit.



#### Tool 2: `tail` (For real-time monitoring)

Prints the bottom portion of a file. Adding `-f` tells the terminal to dynamically stream new updates to your screen as they happen.

```bash
sudo tail -f /var/log/auth.log

```

#### Tool 3: `grep` (For pattern matching)

Filters out all unnecessary text to find exactly what you are looking for.

* **Find failed login attempts:**
```bash
sudo grep "Failed" /var/log/auth.log

```



#### Tool 4: `journald` & `journalctl` (For Systemd environments)

Modern distributions index logs through `journald`. To read this binary log index, you must use the `journalctl` utility:

* 
**View all logs in real-time:** `sudo journalctl -f` 


* 
**View logs for a specific service (e.g., SSH):** `sudo journalctl -u ssh` 


* 
**View logs since the current day's boot:** `sudo journalctl -b`

## 📊 Summary Reference: Windows vs. Linux Logging

| Feature | Windows | Linux |
| --- | --- | --- |
| **Storage Engine** | Windows Event Log Service 

 | <br>`rsyslog` + `systemd-journald` 

 |
| **Primary Directory** | <br>`C:\Windows\System32\winevt\Logs\` 

 | <br>`/var/log/` 

 |
| **Format** | Structured Binary (`.evtx`) 

 | Plain Text (mostly) + Indexed Binary (`journald`) 

 |
| **Default GUI** | Event Viewer (`eventvwr.msc`) 

 | System-dependent (e.g., GNOME Logs), though mostly CLI 

 |
| **Default CLI** | PowerShell (`Get-WinEvent`) 

 | Terminal (`journalctl`, `tail`, `grep`, `less`) 

 |
